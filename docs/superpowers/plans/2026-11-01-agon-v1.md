# Agon v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved Agon PRD across real historical replay, live timing, derived telemetry, comparisons, and honest predictions.

**Architecture:** Six Rust workspace crates own domain, ingest, state, predict, store, and API. React/TypeScript consumes generated Rust types and binary WebSocket snapshots/deltas. A local replay fixture is explicitly synthetic; historical sessions use OpenF1.

**Tech Stack:** Rust, Tokio, Axum, reqwest, serde, ts-rs, MessagePack, PostgreSQL, Redis, React, TypeScript, Vite, ECharts, Playwright, Python offline training/ONNX.

**Spec:** `docs/superpowers/specs/2026-11-01-agon-design.md`; binding requirements: `PRD.md`.

## Global Constraints

- Anonymous, non-commercial fan/educational app; no official logos or raw-feed redistribution endpoint.
- Every forecast includes uncertainty, factors, version, and status; fallback label `basic estimate`.
- Replay 2023 onward, 1x–20x; 2–6 comparison drivers; 1–5 pace horizons; 1,000+ simulations.
- Red flags pause forecasts; SC/VSC/changing weather lower confidence; missing data never becomes zero.
- API keys stay server-side. Validate external input, bound queues/ranges/subscriptions, enforce rate limits.
- Commit format `[type : message]`; no Codex attribution or coauthor trailer.
- Native execution in the current greenfield checkout on a feature branch; preserve main documentation baseline. Design approval authorizes implementation; no further implementation permission gate.

## Review Focus

- Duplicate/reordered lap events must not grow history or corrupt tyre ages (Task 2).
- Seek during inference must not leak future laps or stale predictions (Tasks 2/3/5).
- Partial API schemas, null durations and unavailable geometry must produce partial-data states (Tasks 1/4/6).
- Slow/malicious clients must not allocate unlimited queues, replay data, or telemetry (Task 5).
- Broken local preferences/share query must recover to a valid view without crashing (Task 6).

## File Structure

- `Cargo.toml`, `crates/pitwall-{core,ingest,state,predict,store,api}/`: domain contracts and responsible backend layers; integration/regression tests beside owners.
- `pitwall-web/src/{App,TimingTower,TrackMap,TelemetryPanel,Charts}.tsx`, `stream.ts`, `types/`, `styles.css`: UI, subscriptions, generated domain types.
- `fixtures/`: labelled deterministic synthetic replay; `data/`: ignored imported sessions/models; `metadata/`: cited circuit metadata.
- `training/`: Python acquire/train/export/backtest CLI and split/scoring tests.
- `tests/e2e/`, `playwright.config.ts`: browser acceptance; `scripts/`: local checks/dev/load commands.
- `migrations/`, `compose.yaml`, `Dockerfile`, `.github/workflows/ci.yml`, `README.md`, `docs/acceptance.md`: persistence/deployment and evidence.
